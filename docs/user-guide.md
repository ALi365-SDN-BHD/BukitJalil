# BukitJalil 使用说明

BukitJalil 把每个网站当作一个项目来管理。你用对话告诉 AI 想怎么改网站，AI 在网站的工作副本里修改、检查和构建；你看过差异、预览过效果之后再决定应用还是拒绝。界面里只能查看，不能直接编辑文件。

本文写给使用 BukitJalil 的人。开发和测试见 [README](../README.md)，设计细节见[开发方案](development-plan.md)。

## 1. 准备

| 需要 | 说明 |
| --- | --- |
| macOS（Apple 芯片）或 Linux x64 | 暂不支持 Windows。桌面版目前只有 macOS（Apple 芯片）。Intel Mac 没有官方 Bukit 包，可以自己编译 Bukit 后在设置里填路径 |
| Node 22.19 或更新（推荐 24 LTS） | 从源码运行 BukitJalil 时需要；桌面版自带，不用装 |
| git 2.38 或更新 | 每个网站都是一个 git 仓库，版本、差异、恢复都靠它 |
| Bukit 2.0.15（最低 2.0.11，设置页会自动检查新版本） | 构建网站。可以在 BukitJalil 的设置里一键下载安装，不用提前装 |
| 一个 AI 模型服务商的 API Key | 例如 Anthropic、OpenAI 等 Pi 支持的服务商 |

## 2. 安装和启动

```bash
git clone https://github.com/ALi365-SDN-BHD/BukitJalil.git
cd BukitJalil
git switch pi-harness-ui
corepack enable
pnpm install
pnpm build
pnpm start
```

启动后终端会打印一个登录地址，并自动在浏览器里打开。这个地址只能用一次：换了浏览器或提示"登录已失效"时，在运行 BukitJalil 的终端里按回车，会打印一个新地址。

- 管理界面只监听本机 `127.0.0.1:47880`，网站预览用从 47881 开始的端口。端口被占用时用 `pnpm start --port 48000 --preview-port-base 48001` 换一组
- 应用数据放在 `~/.bukitjalil/`（设置、对话记录、AI 工作副本、构建结果、应用安装的 Bukit 和 ripgrep、API Key）。设置环境变量 `BUKITJALIL_HOME` 可以换位置
- 网站文件夹本身由你选择位置，不在应用目录里

停止 BukitJalil：在终端按 Ctrl+C。正在运行的 AI 会话和构建会被停下，没完成的构建下次启动时标记为"服务重启时中断"；对话记录和 AI 已经做的修改都保留。

### 桌面版

桌面版是同一个 BukitJalil 装在一个窗口里，双击就能用，不需要终端和 Node。

1. 得到安装包：从 GitHub Releases 下载对应平台的文件，可以用同一页的 `SHA256SUMS.txt` 核对；也可以在仓库目录运行 `pnpm package:desktop`，在 `packages/desktop/out/installers/` 里生成本机平台的安装包
   - macOS（Apple Silicon）：`BukitJalil-<版本>-mac-arm64.dmg`（或 `.zip`）
   - Linux（x64）：`.AppImage`（加上执行权限后直接运行）或 `.deb`（`sudo apt install ./BukitJalil-<版本>-linux-amd64.deb`）
   - Windows（x64）：`BukitJalil-<版本>-win-x64.exe`，**预览版**：服务端还没有移植到 Windows，网站功能可能用不了
2. macOS：打开 dmg，把 `BukitJalil.app` 拖进"应用程序"（zip 先解压）
3. macOS 第一次打开：安装包没有 Apple 开发者签名，macOS 会说"无法验证开发者"或"Apple 无法检查其是否包含恶意软件"。先点"完成"，到"系统设置 → 隐私与安全性"，在下面找到 BukitJalil，点"仍要打开"并确认。之后就能正常双击打开

和在终端里运行的区别：

- 窗口自动登录，不需要登录地址
- 新建网站和导入网站时，用"选择文件夹…"按钮打开系统的文件夹选择框
- 网页链接（发布后的网站地址、"在新标签页打开"预览）在默认浏览器里打开
- 关闭窗口不会退出（和其他 Mac 应用一样），点 Dock 图标重新打开；退出用 ⌘Q，BukitJalil 会先停下正在运行的会话和构建
- 帮助菜单里可以打开日志目录和数据目录
- 数据目录同样是 `~/.bukitjalil/`，所以桌面版和 `pnpm start` 看到的是同一批网站和设置。两者不能同时运行：后启动的那个会说明"另一个 BukitJalil 正在使用同一个数据目录"
- 从"应用程序"打开时读不到终端里设置的环境变量，模型的 API Key、发布账号 token 和数据源 token 都在设置里填
- 还是需要 git（macOS 第一次用 git 时会提示安装"命令行开发者工具"）；Bukit 在设置里一键安装

## 3. 第一次使用

第一次打开时，首页会显示"开始使用"清单，按顺序检查五件事，每一步都能直接打开对应的设置：

1. **git**：没有找到或版本太旧时，安装新版 git 并重启 BukitJalil
2. **Bukit**：在设置里点"下载安装 Bukit 最新版本"（当前 2.0.15）。设置页会显示已安装版本和最新版本；有更新时可以一键下载安装。BukitJalil 从 GitHub 下载官方安装包，校验 SHA-256 后安装到应用目录，并且只使用应用目录里安装的 Bukit
3. **提交身份**（设置 → 发布）：你应用改动时用的名字和邮箱，默认取全局 git 设置
4. **AI 模型**：见下一节
5. **第一个网站**：新建或导入，见第 5 节

五步都完成后清单自动收起。

## 4. 设置 AI 模型

点左下角的“设置”打开设置，在“AI 模型”里：

1. 选服务商卡片。支持订阅账号的服务商显示“使用 ... 登录”，点击后按浏览器提示授权（设备代码或手动代码按界面提示操作），无需 API Key。Pi 会把登录凭据保存在本机 `~/.bukitjalil/pi/auth.json`，界面不会显示凭据
2. 也可以填 API Key（只发给这个服务商，界面只显示末四位；也可以用服务商的环境变量，例如 `ANTHROPIC_API_KEY`）
3. 选模型和思考程度，点"测试连接"确认能用
4. 点"使用这个模型"

本地部署：打开设置 → AI 模型 → 本地部署，选择 Ollama、LM Studio、vLLM、llama.cpp 或自定义；填写请求地址、API 格式（OpenAI Completions、OpenAI Responses 或 Anthropic Messages）、模型 ID 和显示名称。API Key 可以留空；保存后会出现在服务商列表里。

设置里还可以安装 ripgrep（固定版本、校验后安装）。不装时 AI 仍然能用，只是查找内容时不能用 grep，只能逐个看文件。环境页也会显示应用内置的 Pi 版本和 npm 上的最新版本；Pi 随应用一起发布，有新版本时请下载新的 BukitJalil 版本更新。

### 数据源

Markdown 是默认数据源，无需在设置里添加。新建网站不选择数据源时，直接使用 starter 模板的 Markdown 内容源，并自动创建 `content/posts`、`content/pages`、`data` 下的 Markdown 文件。

设置 → 数据源只保存 Notion 数据源：

- **Notion**：每个数据源有自己的 integration token 和名称。先在 Notion 里打开数据库页面 → Share，把数据库共享给这个 integration；否则创建网站时看不到它。创建网站时选择数据源，勾选要使用的数据库，并为每个数据库选择用途：文章、页面或数据。每个网站最多一个 Notion 数据源。

创建网站时选的数据库写进 `site.yaml`，选的数据源绑定到这个网站：正式构建用这个数据源的 token 读取数据库。之后替换数据源的 token，下一次构建就用新 token；网站还绑定着的数据源不能删除。导入的网站不会自动绑定任何数据源，需要在网站的数据面板里选择；只给信任的网站绑定，因为它的 `site.yaml` 可以引用这个 token 能读的任何数据库。每个数据源都有名称和 id，id 显示在数据源列表里。

## 5. 新建或导入网站

左栏"网站"下方有两个按钮：

- **新建网站**：填名称、选默认语言和放在哪个文件夹下。需要多语言网站时勾选“多语言网站”，创建后的对话会先询问除默认语言外还需要哪些语言。不选择数据源时默认使用 Markdown，自动创建 Markdown 内容文件；也可以选一个 Notion 数据源，勾选要使用的数据库，并逐个选择用途（文章 / 页面 / 数据）。BukitJalil 从 starter 模板创建网站，提交为第一个版本，然后自动构建一次（选了 Notion 时用所选数据源的 token）
- **导入网站**：选一个已有的 Bukit 网站文件夹（里面有 `site.yaml`），先点"检查这个文件夹"。检查不会修改任何文件
  - 已经是 git 仓库的，以当前分支为正式版本
  - 还不是 git 仓库的，会列出要提交的文件，你确认后才执行 `git init` 并提交
  - 不满足安全规则的（例如有外部插件、符号链接、指向网站外的路径、允许构建时访问内网、特殊的 git 设置），以**只读**方式导入，界面写明原因。只读网站可以查看，不能对话、构建和恢复

网站主页显示位置、默认分支、状态、最近构建和版本历史，顶部的“开始新对话”可以直接进入 AI 对话，也可以手动构建、重新检查。左侧网站行的“更多”菜单可以归档、恢复或移除网站。移除只删除 BukitJalil 自己的工作副本和记录，不会删除你的网站文件夹。

## 6. 和 AI 对话

在网站主页点"开始新对话"，描述你想做的修改，例如"首页加一个常见问题页面，列出五个问题"。第一条消息会自动成为会话标题；之后可以在左侧会话行的“…”菜单里手动重命名。

- Enter 发送，Shift+Enter 换行
- AI 的回答流式显示；它读写的每个文件、运行的每次检查和构建都是一张可以展开的卡片
- AI 工作时可以补充说明："立即补充"在它当前这一步结束后马上告诉它，"稍后发送"等这一轮做完再发。按 Esc 或点"停止"可以停下
- 同一个网站同一时间只有一个对话在运行，其他对话的消息会排队
- 对话可以在左侧会话行的“…”菜单里重命名；删除和“从这里分叉”也都在会话操作里
- AI 只能读写这个网站的工作副本，读不到你的其他文件和密钥，也不能执行任意命令

模型出错时，对话里会写明是哪一类问题（密钥被拒、频率限制或额度、服务过载、对话太长、网络不通）和该怎么做，服务商的原始错误放在"详情"里。

## 7. 审核改动

AI 的改动先留在工作副本里，不会直接进入你的网站。对话下方的"待审核的改动"卡片列出 AI 的改动说明和改动的文件：

- 点"查看差异"，在右栏"改动"面板里逐个文件看差异
- 在"预览"面板切到"改动中"，点"构建改动"可以单独预览 AI 修改后的网站，不影响正式预览
- **应用**：先自动运行 Bukit 的配置检查，通过后改动作为一个提交进入网站的默认分支（作者是 BukitJalil AI，提交者是你），正式预览随后重新构建。检查没通过时什么都不会改，你可以看原因后选择"仍然应用"
- **只应用一部分**：在改动面板里取消勾选不想要的文件；文字文件的修改还可以按处取消（差异里每一处改动前都有勾选框）。按钮变成"应用所选"，只把勾选的部分作为一个提交应用，没勾选的仍留在待审核的改动里，AI 可以接着改，之后再应用或拒绝。新增、删除的文件和二进制文件只能整个选；恢复版本的改动只能整份应用；AI 正在运行时不能勾选
- **拒绝**：丢弃 AI 的修改，网站文件夹保持不变

审核绑定你看到的那一份内容：你审核之后 AI 又改了，必须重新审核。正式版本在这期间有了新提交时，改动会先合并上去并请你重新审核；有冲突时改动集关闭，请让 AI 重新修改。

## 8. 版本历史和恢复

网站主页的"版本历史"列出默认分支上的每个版本，AI 的提交和恢复各有标记。点开一个版本可以看它改了哪些文件和具体差异。

"恢复到这个版本"会生成一个恢复改动，和 AI 的改动一样先审核、再应用，所以恢复本身也会成为一个新版本，之后还能再恢复回来。有待审核的改动时不能恢复，先应用或拒绝它。

## 9. SEO / GEO

每次构建成功后，构建报告里有一节"SEO / GEO"（网站主页"最近构建"里点开一次构建）：

- **SEO**：页面数、错误和警告数，问题按种类分组，点开能看到 Bukit 的说明和涉及的页面
- **还没填网站网址时**：规范链接、分享图片和结构化数据都只能用相对地址，会出现几十个同类警告。这些合成一条提示，告诉 AI 网站的正式网址（例如"网站网址是 https://example.com"）即可解决
- **GEO（AI 搜索）**：0–100 的得分、llms.txt 是否生成、多少页面带 GEO 信息。让 AI 给常见问题、服务、步骤类页面加上 GEO 信息，得分会提高

AI 每次构建也会拿到同样的摘要，但只会处理和这次修改有关或你要求的问题，不会为了消除所有警告乱改网站。

**SEO 面板**（右栏"SEO"，或在构建报告里点"在 SEO 面板里查看"）列出最新一次成功构建的全部问题：

- 顶部是页面数、错误、警告和 GEO 分数，旁边标出和上一次构建相比的增减；切到"改动中"看 AI 改动后的报告，这时和正式版本最新的报告相比
- "页面"下拉框只看一个页面的问题；每种问题标出"新增 / 变多 / 变少"，上次有、这次没有的列在最后"此后已修复"
- **让 AI 修这些问题**：新开一个对话，把当前筛选下的问题（最多 30 条）写进输入框，你可以先改再发送，不会自动发出
- 较早的构建输出会被清理，这时只能看到构建时保存的摘要；同一版本更新的构建失败时，面板提示报告可能已过时

## 10. 发布到 GitHub Pages

网站主页的"发布"一节把**正式版本**（默认分支上最新的已审核版本）发布到 GitHub Pages。

**准备一次**：

1. 在 GitHub 上建好仓库。仓库名是 `用户名.github.io` 时网站在 `https://用户名.github.io/`，其他仓库名在 `https://用户名.github.io/仓库名/`
2. 建一个 token：GitHub 的 Settings → Developer settings → Personal access tokens。推荐 fine-grained token，只选这个仓库，权限 Contents 设为 Read and write
3. 在 BukitJalil 的设置 → 发布 → 发布账号里添加一个 GitHub 账号：填名称和 token。token 保存在本机 `~/.bukitjalil/publish-account-tokens.json`（权限 600），界面只显示末四位；可以保存多个账号，网站发布时选择使用哪一个
   - 从旧版本升级时，全局 GitHub / Notion token 只导入一次。改导入账号或数据源的名称不影响网站关联；删除导入的账号/数据源后，即使环境变量还在，重启也不会自动重建
   - 这些 token 和 Notion 数据源 token 都是本机 0600 明文，依赖操作系统账户权限。不要把 `~/.bukitjalil` 放进共享目录或云同步，建议开启全盘加密；Windows 上文件权限不是完整的 NTFS ACL
4. 在网站主页的"发布"区点"部署设置"：选择发布账号，填写仓库（`owner/name`，例如 `alice/my-blog`），分支默认 `gh-pages`，有自定义域名再填。保存时会检查这个 token 对仓库是否有 Contents 写权限，并把 `deploy` 段、`site.url` 和 `site.baseUrl` 写进 `site.yaml`。没有自定义域名的项目站点，`site.baseUrl` 是 `/<仓库名>/`：之后的预览也会打开在这个路径下，和发布后的网址一致，模板或正文里漏写这个前缀的链接在预览里就会坏掉。`site.baseUrl` 只能用字母、数字和 `. _ ~ -`，以 `/` 分隔，否则预览构建会失败（结果为"site.baseUrl 不是可以用来预览的路径"）
5. 在 GitHub 仓库的 Settings → Pages 里，把 Build and deployment 设为 Deploy from a branch，分支选 `gh-pages`（或你设置的分支）。第一次发布后这个分支才会出现

**发布**：点"发布"，确认对话框会写明仓库、分支和要发布的版本。确认后 BukitJalil 在本机依次做安全检查、配置检查、诊断、构建、发布审计，全部通过才推送；任何一步失败都不会推送，发布记录里写明是哪一步和原因。推送会覆盖目标分支上的网站内容，GitHub Pages 通常要一两分钟才显示新内容。

**发布审计的警告**：发布记录里有"发布审计"摘要。警告不会阻止发布。多语言网站常见三类警告：

- `publish.sitemap_missing_route`：每种语言各有一个 sitemap。让 AI 在 `site.yaml` 加 `sitemapMode: merged`，就会在根目录生成一个合并的 sitemap，这类警告消失
- `publish.rss_missing_route`、`publish.search_missing_route`：RSS 和站内搜索索引按语言分开生成，Bukit 2.0.12 的审计只看根目录，所以会报缺少。网站本身没有问题，可以不处理

**多语言网站的首页地址**：Bukit 只生成 `/zh-CN/`、`/en-US/` 这样的语言目录，根目录没有首页。发布时 BukitJalil 会在根目录补一个跳转页，打开网站地址会转到默认语言（`site.defaultLanguage`）的首页
- `publish.time_missing`：页面模板没有显示日期的 `<time>` 元素，可以让 AI 在文章模板里加上

## 11. 右栏面板

| 面板 | 看什么 |
| --- | --- |
| 预览 | Bukit 构建出的网站，可以在新标签页打开；"正式版本 / 改动中"切换 |
| 改动 | 待审核改动的文件和差异 |
| 文件 | 网站的目录树和文件内容，Markdown、图片可以预览 |
| 配置 | `site.yaml` 的概要和原文 |
| 主题 | 当前主题的布局、资源、静态文件和参数 |
| 数据 | 内容源：Markdown 集合的文件和字段、数据文件（表格只显示第一条作为示例）；Notion 源显示配置，并可以绑定或解绑 Notion 数据源 |
| SEO | 最新一次成功构建的全部 SEO 问题，按页面筛选，和上一次构建对比，可以让 AI 修 |

文件、配置、主题、数据面板也能切到"改动中"，看 AI 修改后的样子。

## 12. 外观和操作

- **界面语言**：设置 → 通用，简体中文或 English
- **外观**：设置 → 通用，跟随系统、浅色或深色
- **键盘快捷键**：设置 → 通用 → 键盘快捷键 → 查看；在主界面按 `?` 也可以打开
- **Git 版本**：设置 → 环境显示已安装版本和 Git 官方最新版本。未安装时显示“安装 Git”，有新版时显示“更新到 x.y.z”。macOS/Linux 有 Homebrew 时通过 Homebrew 安装或更新；Windows 从 Git for Windows 官方发布页下载 MinGit 并安装到应用数据目录，立即切换。没有自动安装方式时显示当前平台检测到的包管理器命令（macOS 的 Xcode 命令行工具、Linux 的 apt/dnf/pacman/zypper/apk、Windows 的 winget/Chocolatey）；没有检测到包管理器时提示手动安装。“检查全部更新”会同时刷新 Bukit、ripgrep、Pi 和 Git 的最新版本，Git 行右侧的刷新图标只检查 Git。手动安装到新路径后需要重启 BukitJalil
- **窄屏**：浏览器宽度小于 768 像素（例如手机）时，三栏改为一次显示一栏，底部有"网站 / 对话 / 面板"三个标签切换；切换时没发出的消息和预览都还在
- **键盘快捷键**：

| 按键 | 作用 |
| --- | --- |
| Enter | 发送消息（在输入框里） |
| Shift+Enter | 消息换行 |
| Esc | AI 工作时停止（在输入框里） |
| Alt+1 … Alt+7 | 切换右栏面板：预览、改动、文件、配置、主题、数据、SEO（在文本框以外；Mac 上 Alt 是 Option 键） |
| ? | 显示快捷键列表（在文本框以外） |

## 13. 常见问题

**提示"登录已失效"**：在运行 BukitJalil 的终端里按回车，打开新打印的地址。

**顶栏显示"与服务器的连接已断开，正在重试"**：BukitJalil 停止了或电脑休眠过。确认终端里服务还在运行，恢复后界面会自动重连。

**构建失败**：在网站主页的"最近构建"里点开构建报告，看结果、警告和错误。"未通过构建前安全检查"会列出原因（例如加了外部插件或指向网站外的路径），让 AI 改回去即可。"Bukit 运行失败"时先看输出重试，反复出现就在设置里检查或重新安装 Bukit。

**磁盘已满、只读或没有权限**：界面会直接写明。腾出空间或换一个可写的位置后重试。

**网站显示"只读"**：导入时没通过安全规则，原因写在网站主页。在网站文件夹里自己修正（例如删除外部插件目录、去掉不允许的 git 设置）后点"重新检查"。

**网站使用 Notion 内容源**：在设置 → 数据源里添加一个 Notion 数据源，填入它的 integration token；在 Notion 中把数据库共享给这个 integration，新建网站时才能选中它。每个网站最多一个 Notion 数据源，可以同时使用它的多个数据库；正式构建和发布使用这个数据源的 token；导入的网站要先在数据面板里绑定数据源。AI 的改动在应用前无法用 Bukit 检查，也不能预览：应用时会提示没有检查，请看应用后正式构建的结果。

**发布失败**：在"发布"一节点开发布记录。推送这一步失败多半是 token 的问题：没有这个仓库的 Contents 写权限、已过期，或者仓库名写错了；在设置 → 发布里更新账号 token，或在网站的"部署设置"里换账号、改仓库后重试。推送成功但网站没更新时，检查 GitHub 仓库的 Pages 设置是否从对应分支发布。

**桌面版提示"另一个 BukitJalil 正在使用同一个数据目录"**：在终端里用 `pnpm start` 或 `pnpm dev` 启动的 BukitJalil 还在运行。先把它停下（终端里按 Ctrl+C），再点窗口里的"重新启动"。如果确定没有别的 BukitJalil 在运行，删除 `~/.bukitjalil/server.lock` 后重试。

**桌面版提示"服务意外停止"**：点"重新启动"。反复出现时，帮助菜单 → 打开日志目录，看 `server.log` 最后几行。

**应用时提示网站文件夹有未提交的改动或不在正式分支上**：你在 BukitJalil 之外改过网站文件夹。先在那里提交或撤销、切回正式分支，再应用。

## 14. 目前的限制

- 只支持 macOS（Apple 芯片）和 Linux x64，没有 Windows 版；桌面版只有 macOS（Apple 芯片），没有开发者签名和自动更新
- 只能发布到 GitHub Pages；Cloudflare Pages 和自己的服务器以后再做
- 不支持 Bukit 的外部插件，只允许内置插件
- Notion 数据源需要每个数据源自己的 token，并且要在 Notion 中把数据库共享给对应 integration；不同 Notion 工作区的数据源可以分别配置，但一个网站只能选一个 Notion 数据源
