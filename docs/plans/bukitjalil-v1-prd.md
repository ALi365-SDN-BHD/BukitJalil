# BukitJalil V1 PRD

## 1. 产品概述

### 1.1 产品名称

`BukitJalil V1`

### 1.2 产品定位

BukitJalil V1 是一个面向 Bukit 的 AI 建站桌面工作台。

它的目标不是在第一版就完成完整的结构化网站生产平台，而是先做成与 `AIBuilding` 等价、可稳定使用、可持续演进的产品形态。

### 1.3 版本策略

V1 采用渐进式产品策略：

- 先做成一个完整可用的 AI 建站工作台；
- 先跑通项目创建、AI 对话生成、文件写入、Bukit 构建、预览、部署的完整链路；
- 在此基础上逐步增加结构化 schema、内容草稿、审批、状态流转等高级能力。

一句话定义：

```text
BukitJalil V1 = 可替代 AIBuilding 的 Bukit AI 建站桌面工作台
```

## 2. 产品目标

### 2.1 核心目标

- 让用户通过自然语言完成网站项目创建与迭代；
- 让用户可以在一个桌面工作台中完成生成、修改、构建、预览和部署；
- 为未来从文件驱动演进到结构化驱动预留清晰边界；
- 形成 BukitJalil 后续版本的可运行基础底座。

### 2.2 V1 成功标准

BukitJalil V1 达成成功标准时，用户应能够：

- 创建一个本地网站项目；
- 与 AI 对话生成网站 demo；
- 将生成结果落入项目目录；
- 使用 Bukit 成功构建项目；
- 在本地预览构建结果；
- 将网站部署到至少一个目标平台；
- 在重启应用后恢复项目、设置与会话状态。

## 3. 目标用户

### 3.1 主要用户

- 使用 Bukit 的开发者；
- 需要快速生成静态网站的个人开发者；
- 希望统一管理站点配置、主题、构建与部署流程的小团队；
- 熟悉技术流程，但希望减少手工编辑和 CLI 操作的用户。

### 3.2 暂不优先覆盖的用户

- 纯非技术型内容运营用户；
- 多人协作团队；
- SaaS 平台订阅用户；
- 以移动端为主要工作设备的用户。

## 4. 核心场景

### 4.1 新建站点

用户创建一个新项目，通过对话描述网站类型、风格、内容来源和部署目标，AI 生成 demo、配置和模板文件。

### 4.2 迭代修改

用户对生成结果不满意，通过继续对话要求调整布局、配色、内容结构或模板文件，AI 自动修改项目内容并给出新预览。

### 4.3 构建验证

用户在工作台中触发 Bukit 构建，查看构建日志，并对编译问题进行修复与再次验证。

### 4.4 发布上线

用户选择目标部署平台，将构建结果发布到线上环境。

## 5. 产品范围

### 5.1 必须具备的功能

#### 5.1.1 项目管理

- 创建项目；
- 打开项目；
- 删除项目；
- 保存项目元数据；
- 恢复最近编辑项目。

#### 5.1.2 AI 工作台

- 对话式输入；
- 显示消息历史；
- 切换 AI Provider；
- 执行工具调用；
- 对敏感操作进行用户确认；
- 保存和恢复聊天会话。

#### 5.1.3 主题与页面生成

- 生成 HTML、CSS、JS demo；
- 支持多轮迭代修改；
- 将 demo 确认为 Bukit 模板文件；
- 导出主题 ZIP 包。

#### 5.1.4 项目文件管理

- 浏览项目文件树；
- 读取文件内容；
- 写入文件内容；
- 查看生成代码；
- 查看构建输出和运行日志。

#### 5.1.5 Bukit 集成

- 生成 `site.yaml`；
- 执行 `bukit build`；
- 执行 `bukit preview`；
- 展示构建输出；
- 在应用内预览结果。

#### 5.1.6 部署能力

- 管理部署平台配置；
- 至少支持 GitHub Pages；
- 为 Vercel、Netlify、Cloudflare Pages 预留或恢复基础支持；
- 展示部署结果与访问地址。

#### 5.1.7 设置中心

- 配置 Bukit 路径；
- 配置 AI Provider；
- 配置默认模型；
- 配置文档路径；
- 配置部署平台。

#### 5.1.8 本地存储

- LiteDB 持久化；
- 本地项目目录；
- 项目日志；
- 聊天会话恢复；
- 本地知识库索引。

### 5.2 明确不属于 V1 的能力

- Web SaaS 版本；
- 多用户协作；
- 账号体系；
- 订阅与计费；
- 远程构建主流程；
- 移动端完整工作台；
- 完整的结构化 schema/content 审批系统；
- 团队工作流与模板市场。

## 6. 产品信息架构

### 6.1 顶层导航

BukitJalil V1 建议包含以下主页面：

- `Projects`
- `Workspace`
- `Themes`
- `Platforms`
- `Settings`

### 6.2 Workspace 工作区

AI 工作区建议包含以下视图：

- `Preview`
- `Code`
- `Files`
- `Build`
- `Log`
- `Chat`

### 6.3 工作台布局

推荐采用桌面优先布局：

```text
左侧内容区（Preview/Code/Files/Build/Log）
右侧 AI Chat 区
顶部工具栏
```

这种形态与 AIBuilding 的用户习惯一致，也最适合作为 V1 的稳定入口。

## 7. 用户流程

### 7.1 新项目流程

```text
创建项目
-> 进入 AI 工作台
-> 描述网站需求
-> AI 生成 demo
-> 用户反馈修改
-> 确认 demo
-> 写入 Bukit 模板与配置
-> build
-> preview
-> deploy
```

### 7.2 已有项目流程

```text
打开已有项目
-> 恢复聊天会话
-> 查看文件/预览/日志
-> 继续对话修改
-> 再次 build
-> 再次 deploy
```

## 8. V1 数据模型

V1 不追求完整结构化建站模型，优先使用适合文件驱动工作流的数据结构。

### 8.1 Project

用途：

- 表示一个 Bukit 项目；
- 关联项目目录、配置、主题和部署目标。

建议字段：

- `Id`
- `Name`
- `Description`
- `ThemeId`
- `CreatedAt`
- `UpdatedAt`
- `SiteName`
- `SiteTitle`
- `SiteBaseUrl`
- `SiteUrl`
- `SiteLanguage`
- `ContentProvider`
- `ThemeName`
- `ExtraConfig`
- `DeployPlatformId`
- `ModelId`

### 8.2 Theme

用途：

- 保存 AI 生成的主题文件。

建议字段：

- `Id`
- `Name`
- `Type`
- `Files`
- `SourceProjectId`
- `CreatedAt`
- `ModelId`

### 8.3 AppSettings

用途：

- 保存 Provider 配置、Bukit 路径、文档路径等应用设置。

### 8.4 DeployPlatform

用途：

- 保存部署平台配置和凭据引用。

### 8.5 ChatSession

用途：

- 保存工作台对话历史与阶段状态。

### 8.6 ProjectLog

用途：

- 保存聊天、文件修改、构建、部署、系统、错误日志。

## 10. 与 AIBuilding 的关系

### 10.1 V1 产品关系

BukitJalil V1 的产品形态应与 AIBuilding 接近：

- 同样提供 AI 工作台；
- 同样支持文件驱动的项目编辑；
- 同样支持 Bukit 构建与部署；
- 同样保留本地桌面工作方式。

### 10.2 V1 技术策略

BukitJalil V1 不应简单复制旧代码，而应采用以下原则：

- 产品能力先对齐；
- 基础设施优先复用；
- UI 与工作流做更清晰的职责拆分；
- 提前为未来结构化演进保留接口。

## 11. AIBuilding 到 BukitJalil 的迁移策略

### 11.1 直接复用

以下能力可以优先迁移：

- Provider 抽象与注册表；
- LiteDB 数据库接入；
- 项目目录管理；
- 聊天会话持久化；
- Bukit CLI 集成；
- 部署服务；
- 本地知识库索引与检索；
- 基础日志能力。

### 11.2 重构后复用

以下能力建议重构后再迁移：

- `AiStudio` 工作台；
- `ToolExecutor`；
- `PromptBuilder`；
- 各类 Store 命名和职责划分；
- 与旧产品名称强绑定的数据模型。

### 11.3 延后实现

以下能力建议放到 V1.5 或 V2：

- `SiteDefinition`
- `ContentDraft`
- `ArticleDraft`
- Schema 校验服务
- Prompt 模板渲染器
- 审批流与状态流转
- 远程构建服务

## 12. V1 版本计划

### Phase 1: 基础宿主

- 创建新的解决方案结构；
- 建立 MAUI Blazor 宿主；
- 接入 Core 和 Infrastructure；
- 跑通基础启动流程。

### Phase 2: 存储与配置

- 接入 LiteDB；
- 建立 Settings、Projects、Platforms 的基础存储；
- 恢复本地项目目录能力。

### Phase 3: AI 工作台

- 建立工作台外壳；
- 接入聊天历史；
- 接入 Provider 切换；
- 接入工具调用与确认流程。

### Phase 4: 文件与主题

- 支持 demo 生成；
- 支持文件树浏览；
- 支持文件写入和读取；
- 支持主题导出。

### Phase 5: Bukit 工作流

- 生成 `site.yaml`；
- 跑通 build；
- 跑通 preview；
- 展示构建日志。

### Phase 6: 部署

- 跑通 GitHub Pages；
- 补回其他平台的基础能力；
- 完成平台配置管理。

### Phase 7: 稳定化

- 优化错误处理；
- 增加日志与诊断；
- 增加必要测试；
- 完成文档补充。

## 13. V1 之后的演进

### V1.5

- 在现有工作台上引入部分结构化草稿能力；
- 增加校验提示和更清晰的生成记录；
- 不替换 V1 主流程。

### V2

- 从文件驱动逐步过渡到结构化驱动；
- 增加 `SiteDefinition`、`ContentDraft`、审批与状态流转；
- 建立更清晰的生成和发布流水线。

### V3

- 增加 Web 控制台；
- 增加多用户协作；
- 增加远程构建和 SaaS 化能力。

## 14. 一句话总结

```text
BukitJalil V1 的正确目标，不是一步做成最终平台，而是先做成一个更干净、更可演进的 AIBuilding 2.0。
```
