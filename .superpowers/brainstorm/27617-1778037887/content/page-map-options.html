BukitJalil 页面地图方向

目标：保留 AIBuilding 的视觉气质与操作习惯，但按 BukitJalil 的新信息架构重组，桌面端优先，界面全中文。

方案 A

AIBuilding 等价映射

最像旧产品，迁移阻力最低，但结构化工作流表达会比较弱。

应用结构
项目 / 工作台 / 部署 / 设置
顶部工具栏
左：预览 / 代码 / 文件 / 构建 / 日志
右：AI 对话

优点

  • 最接近 AIBuilding 习惯
  • 用户迁移成本低

代价

  • 结构 / 内容 / 审核主线不够清晰
  • 容易回到“功能面板堆叠”
方案 B（推荐）

AIBuilding 外形 + 新信息架构

保留熟悉的工具台密度与右侧 AI 工作方式，但把主流程重组为可审核、可回放的结构化工作流。

应用结构
项目 / 最近 / 部署 / 设置 / 诊断
顶部项目栏 + 全局动作
工作台 Tab：总览 / 对话 / 结构 / 内容 / 构建 / 部署 / 历史
主区：左侧当前任务面板，中间主编辑区，右侧 AI / Inspector

优点

  • 既像 AIBuilding，又更适合 BukitJalil V1
  • 结构化工作流清晰，便于后续审核和自动化

代价

  • 需要重新设计页面地图与面板边界
  • 不是简单 1:1 复刻
方案 C

流程编排优先

按“项目建立 -> 结构生成 -> 内容生产 -> 构建部署”做成向导式工作台，最现代，但最不像 AIBuilding。

应用结构
项目 / 队列 / 历史 / 设置
头部进度条
步骤：项目 -> 结构 -> 内容 -> 预览 -> 构建 -> 部署
AI 作为每一步的协同面板

优点

  • 流程最清楚
  • 最容易加入审核门禁

代价

  • 偏离 AIBuilding 体验较大
  • 老用户会觉得陌生
